2.1 Implementation: Login Expiry After 3 Weeks

Approach A: Server-Side (RECOMMENDED for true security)
  - Server validates token expiration
  - Client stores expiry date from server response
  - On app start, check expiry; if expired, force logout

Approach B: Client-Side Only (Vulnerable to tampering, but adds barrier)
  - Store first login timestamp in secure storage
  - On each app launch, check if (current_date - first_login) > 21 days
  - If expired, clear credentials and redirect to login
  - WARNING: Can be bypassed by clearing app data or changing device time

Recommended Hybrid Approach:
  - Store both: local expiry check + server validation on sync
  - When offline, allow grace period but flag for server review
  - When online, enforce server expiry strictly

Code Example (lib/services/auth_service.dart):

class AuthService {
  static const _firstLoginKey = 'first_login_timestamp';
  static const _lastLoginKey = 'last_login_timestamp';
  static const _ expiryCheckKey = 'expiry_check_date';
  static const int MAX_LOGIN_DAYS = 21;

  // Call after successful login
  static Future<void> initializeLoginPeriod() async {
    final secureStore = const FlutterSecureStorage();
    final now = DateTime.now();

    // Set first login if not exists
    final firstLogin = await secureStore.read(key: _firstLoginKey);
    if (firstLogin == null) {
      await secureStore.write(
        key: _firstLoginKey,
        value: now.millisecondsSinceEpoch.toString(),
      );
    }

    // Always update last login
    await secureStore.write(
      key: _lastLoginKey,
      value: now.millisecondsSinceEpoch.toString(),
    );
  }

  static Future<bool> isLoginExpired() async {
    final secureStore = const FlutterSecureStorage();
    final firstLoginStr = await secureStore.read(key: _firstLoginKey);

    if (firstLoginStr == null) return false; // No login yet

    final firstLogin = DateTime.fromMillisecondsSinceEpoch(
      int.parse(firstLoginStr),
    );
    final difference = DateTime.now().difference(firstLogin);

    return difference.inDays >= MAX_LOGIN_DAYS;
  }

  static Future<void> enforceLoginExpiry() async {
    if (await isLoginExpired()) {
      await logout(); // Clear all credentials
      throw LoginExpiredException('Login period expired. Please re-authenticate.');
    }
  }
}

import android.content.pm.PackageManager
import android.os.Build
import androidx.core.content.edit

class VersionProtection {
    companion object {
        private const val PREFS_NAME = "app_protection_prefs"
        private const val KEY_MIN_VERSION = "min_version_code"
        private const val KEY_INSTALL_DATE = "install_date"

        fun verifyVersion(context: Context): Boolean {
            val prefs = context.getSharedPreferences(PREFS_NAME, Context.MODE_PRIVATE)

            val currentVersion = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.P) {
                context.packageManager.getPackageInfo(
                    context.packageName,
                    PackageManager.PackageInfoFlags.of(0)
                ).longVersionCode.toInt()
            } else {
                @Suppress("DEPRECATION")
                context.packageManager.getPackageInfo(
                    context.packageName,
                    0
                ).versionCode
            }

            val savedMinVersion = prefs.getInt(KEY_MIN_VERSION, currentVersion)

            // If current version is lower than saved minimum, block
            if (currentVersion < savedMinVersion) {
                return false // Downgrade detected
            }

            // Update minimum if this is a newer version
            if (currentVersion > savedMinVersion) {
                prefs.edit().putInt(KEY_MIN_VERSION, currentVersion).apply()
            }

            return true
        }
    }
}

import 'dart:io';
import 'package:package_info_plus/package_info_plus.dart';
import 'package:flutter_secure_storage/flutter_secure_storage.dart';

class VersionService {
  static const _storage = FlutterSecureStorage();
  static const _minVersionKey = 'min_allowed_version_code';

  static Future<bool> isVersionDowngrade() async {
    final packageInfo = await PackageInfo.fromPlatform();
    final currentVersionCode = int.parse(packageInfo.buildNumber);

    final savedMin = await _storage.read(key: _minVersionKey);
    if (savedMin == null) {
      await _storage.write(
        key: _minVersionKey,
        value: currentVersionCode.toString(),
      );
      return false;
    }

    final minVersion = int.parse(savedMin);

    if (currentVersionCode < minVersion) {
      return true; // DOWNGRADE DETECTED
    }

    if (currentVersionCode > minVersion) {
      await _storage.write(
        key: _minVersionKey,
        value: currentVersionCode.toString(),
      );
    }

    return false;
  }

  static Future<void> handleVersionCheck() async {
    if (await isVersionDowngrade()) {
      // Clear sensitive data and show blocked screen
      await _clearAppData();
      throw VersionDowngradeException(
        'Invalid app version detected. Please update to the latest version.'
      );
    }
  }
}

import 'dart:io';
import 'package:device_info_plus/device_info_plus.dart';
import 'package:root_detection/root_detection.dart';

class IntegrityService {
  static Future<bool> isDeviceSecure() async {
    // Check for root/jailbreak
    final isRooted = await RootDetection.isRooted;

    // Check for debug mode
    final isDebug = Platform.isAndroid
        ? await _isAndroidDebug()
        : await _isIOSDebug();

    // Check for known security threats
    if (isRooted || isDebug) {
      return false;
    }

    return true;
  }

  static Future<bool> _isAndroidDebug() async {
    final androidInfo = await DeviceInfoPlugin().androidInfo;
    return androidInfo.isSecure ?? false; // false if debug/rooted
  }

  static Future<bool> _isIOSDebug() async {
    final iosInfo = await DeviceInfoPlugin().iosInfo;
    return !iosInfo.model.contains("Simulator"); // Basic check
  }
}

4.1 Hardware-Based Device Fingerprinting

Generate unique device fingerprint and bind account to it.

Implementation Strategy:

Option A: Device ID + Hardware Hash (Best for offline)
  - Combine multiple hardware identifiers
  - Hash the combination for privacy
  - Store fingerprint on server and locally
  - On new install, compare with stored fingerprint

Option B: Android ID / iOS Identifier for Vendor (IDFV)
  - Platform-specific, limited by privacy restrictions
  - May change on factory reset

Option C: UUID stored in secure storage + hardware fingerprint
  - Create persistent device ID
  - Cannot be reset by app reinstall (if stored in keystore)

Recommended Hybrid Approach:

lib/services/device_fingerprint_service.dart:
---------------------------------------------
import 'dart:io';
import 'dart:convert';
import 'dart:math';
import 'package:crypto/crypto.dart';
import 'package:device_info_plus/device_info_plus.dart';
import 'package:flutter_secure_storage/flutter_secure_storage.dart';

class DeviceFingerprintService {
  static const _storage = FlutterSecureStorage();
  static const _fingerprintKey = 'device_fingerprint';
  static final _deviceInfo = DeviceInfoPlugin();

  static Future<String> generateFingerprint() async {
    List<String> identifiers = [];

    try {
      if (Platform.isAndroid) {
        final androidInfo = await _deviceInfo.androidInfo;
        identifiers.addAll([
          androidInfo.androidId ?? 'unknown_android_id',
          androidInfo.board ?? 'unknown_board',
          androidInfo.brand ?? 'unknown_brand',
          androidInfo.device ?? 'unknown_device',
          androidInfo.hardware ?? 'unknown_hardware',
          androidInfo.host ?? 'unknown_host',
          androidInfo.id ?? 'unknown_id',
          androidInfo.model ?? 'unknown_model',
          androidInfo.product ?? 'unknown_product',
          if (androidInfo.serialNumber != null)
            androidInfo.serialNumber!,
        ]);
      } else if (Platform.isIOS) {
        final iosInfo = await _deviceInfo.iosInfo;
        identifiers.addAll([
          iosInfo.identifierForVendor ?? 'unknown_ios_vendor',
          iosInfo.model ?? 'unknown_model',
          iosInfo.systemName ?? 'unknown_system',
          iosInfo.systemVersion ?? 'unknown_version',
          iosInfo.localizedModel ?? 'unknown_localized',
        ]);
      }
    } catch (e) {
      debugPrint('Error collecting device info: $e');
    }

    // Add storage-specific identifier (persists across app reinstalls on same device)
    final storageId = await _storage.read(key: 'persistent_device_id');
    if (storageId == null) {
      final newId = _generateRandomId();
      await _storage.write(key: 'persistent_device_id', value: newId);
      identifiers.add(newId);
    } else {
      identifiers.add(storageId);
    }

    // Create hash of combined identifiers
    final combined = identifiers.join('|');
    final bytes = utf8.encode(combined);
    final hash = sha256.convert(bytes);

    return hash.toString();
  }

  static String _generateRandomId() {
    final random = Random.secure();
    final values = List<int>.generate(32, (i) => random.nextInt(256));
    return base64Url.encode(values).replaceAll('=', '');
  }

  static Future<String> getOrCreateFingerprint() async {
    final stored = await _storage.read(key: _fingerprintKey);
    if (stored != null) {
      return stored;
    }

    final fingerprint = await generateFingerprint();
    await _storage.write(key: _fingerprintKey, value: fingerprint);
    return fingerprint;
  }

  static Future<bool> isDeviceRegistered(String serverFingerprint) async {
    final localFingerprint = await getOrCreateFingerprint();
    return localFingerprint == serverFingerprint;
  }

  static Future<void> registerDeviceOnServer(String agentId) async {

SECTION 5: OFFLINE CONSIDERATIONS & WORKAROUNDS
================================================================================

Challenge: App works offline → security checks must work without network.

5.1 Offline Login Validation
   Problem: Cannot validate credentials against server when offline.

   Solutions:
   a) Grace Period: Allow offline login for 7 days with warning banner
   b) cached credentials: Verify against cached hash (security risk)
   c) Force online sync: Block login if offline for >24 hours
   d) Hybrid: Allow limited features offline, block sensitive operations

   Recommended (c): Since it's government collection, require online sync
   daily. Block login if offline >24h AND last sync >24h ago.

   Code:
   - Store last_sync_timestamp in secure storage
   - On app start: check if now - last_sync > 24h and device is offline
   - If true: show "Please connect to internet to verify credentials" screen

5.2 Offline Device Verification
   - Fingerprint is stored locally and on server
   - When offline: compare local fingerprint with stored fingerprint
   - If match: allow access (secure since stored in keystore)
   - When online: re-verify with server for audit

5.3 Offline Version Check
   - Store last_known_good_version_code in secure storage
   - On launch: if current version < stored version → downgrade detected
   - Only updates when app successfully launches (not on failed launch)

5.4 Offline Expiry Check
   - Store expiry_date locally (derived from first_login + 21 days)
   - Check against device time (vulnerable to time change)
   - Mitigation: on each successful online sync, update expiry from server
   - If offline and expiry passed → block access

SECTION 11: RISKS & MITIGATIONS
================================================================================

Risk 1: Users lock themselves out after 21 days
  Mitigation:
    - Send email reminder 5 days before expiry
    - Provide admin override portal
    - Allow 3-day grace period with admin approval

Risk 2: Device malfunction/factory reset requires re-registration
  Mitigation:
    - Allow admin to reset device binding via dashboard
    - Verify identity through support ticket + agent ID verification
    - Audit all device resets

Risk 3: Rooted device users circumvent protections
  Mitigation:
    - Implement strong root detection
    - Require online validation every 24h
    - Log security events for monitoring
    - Consider remote wipe capability

Risk 4: Offline app cannot reach server for validation
  Mitigation:
    - Implement 24h offline grace period
    - Cache last known good state
    - Block sensitive operations if offline too long

Risk 5: Timezone manipulation to bypass expiry
  Mitigation:
    - Use UTC timestamps exclusively
    - On online sync, verify with server time
    - Detect significant time jumps (e.g., >1 day change)

Risk 6: Backup/restore from cloud (Google Drive/iCloud) restores
        fingerprint to new device
  Mitigation:
    - Include app-specific salt in fingerprint generation
    - On fingerprint mismatch, require online verification
    - Flag as potential security incident

CONCLUSION

The E-Revenue app currently has zero authentication, making it highly
vulnerable to unauthorized use. Your requested features are essential for
a government financial application.

Priority Actions:
1. Remove hardcoded credentials immediately
2. Implement real backend authentication
3. Add 21-day login expiry (server-enforced)
4. Prevent version downgrade via version_code check
5. Implement device fingerprinting for single-device binding

The biggest challenge is the offline nature. Plan for:
- Online sync requirement every 24h
- Grace periods for network outages
- Manual admin override process for legitimate edge cases

Success depends on server-side implementation. Client-side checks alone
can be bypassed by determined attackers.

All recommendations assume you have a backend server ready. If you don't,
priority #0 is building the authentication backend.
